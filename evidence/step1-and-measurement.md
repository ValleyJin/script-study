# 1단계 조건과 측정 방법을 뒷받침하는 근거

2026-10-01, darwin arm64, Apple clang version 17.0.0 (clang-1700.6.3.2).
`docs/02-만들-언어의-범위.md`의 1단계 조건과 "어떻게 재는가" 절이 이 결과를 근거로 삼는다.

## 1. 왕복 검사는 파서의 우선순위 오류를 잡지 못한다

소스: `evidence/roundtrip-blind-spot.py` · 명령: `python3 evidence/roundtrip-blind-spot.py`

```
원문                : 1 + 2 * 3 - 4
틀린 파서가 만든 트리 : (1 + (2 * (3 - 4)))
올바른 트리          : ((1 + (2 * 3)) - 4)
다시 파싱해 찍은 것   : (1 + (2 * (3 - 4)))
왕복 일치            : True
```

트리를 글로 찍고 다시 파싱해 또 찍는 검사는 **프린터와 파서가 서로 맞는지만** 본다.
파서가 문법과 어긋나도 자기 일관되게 어긋나면 왕복 출력이 글자까지 같다. 괄호를 모두
붙여 찍어도 마찬가지다. 그래서 1단계 조건에 괄호를 다 붙인 기대 트리를 손으로 적어 두는
검사를 함께 둔다.

## 2. `ru_maxrss`의 단위는 플랫폼마다 다르다

소스: `evidence/maxrss-unit.c` · 명령: `cc -O2 -o /tmp/rss evidence/maxrss-unit.c && /tmp/rss 200`

```
50 MB 만진 뒤 ru_maxrss = 53870592  (sink=0)
  바이트로 읽으면 51.4 MB
  KB로  읽으면 52608.0 MB
200 MB 만진 뒤 ru_maxrss = 211156992  (sink=0)
  바이트로 읽으면 201.4 MB
  KB로  읽으면 206208.0 MB
400 MB 만진 뒤 ru_maxrss = 420872192  (sink=0)
  바이트로 읽으면 401.4 MB
  KB로  읽으면 411008.0 MB
```

이 기계에서 `ru_maxrss`는 **바이트**다. 200MB를 만지면 211156992가 나온다. Linux는
킬로바이트 단위라서, 단위를 적지 않으면 기록한 수를 뒤에 읽을 수 없다.

**처음 잰 값이 틀렸다.** `malloc`과 `memset`만 하고 그 버퍼를 쓰지 않으면 `-O2`가
둘을 지워 버려서 1409024가 나왔다. 만진 메모리를 실제로 읽어 `volatile`에 넣고서야
맞는 값이 나왔다. 측정 코드가 최적화로 사라지는지 먼저 확인해야 한다.
