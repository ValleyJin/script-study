# 기준 테스트가 1, 2 를 찍는 진짜 까닭

2026-10-04. `study/02` 와 `study/04` 가 적었던 까닭이 틀렸다. 고친 근거다.

## 틀린 주장

두 문서가 이렇게 적었다.

> 대입이 못 찾을 때 새로 만들게 두면 기준 테스트가 `1`, `1` 을 찍는다.

## 실험

`src/` 를 복사해 `slEnvSet` 을 두 가지로 고쳐 돌렸다.

```c
/* 가설 A: 못 찾는 경로에 새로 만들기를 넣는다 */
slEnvDefine(env, name, value);
return true;

/* 가설 B: 체인을 거슬러 오르지 않고 가장 안쪽 환경만 본다 */
if (env != NULL) {
  int i = indexOf(env, name);
  if (i >= 0) { env->values[i] = value; return true; }
  slEnvDefine(env, name, value);
  return true;
}
```

| 무엇을 고쳤나 | `./sl --walk tests/closure.sl` |
|---|---|
| 고치지 않음 | `1 2` |
| 가설 A | `1 2` |
| 가설 B | `1 1` |

## 무엇이 틀렸나

가설 A 가 `1`, `2` 를 그대로 찍는다. `n` 은 `counter` 의 호출 환경에 있어 체인에서 늘
찾히므로 "못 찾을 때" 경로를 아예 밟지 않는다. 그 경로를 고쳐도 이 테스트는 안 움직인다.

`1`, `1` 을 만드는 것은 가설 B 다. **체인을 거슬러 오르지 않고 가장 안쪽 환경만 보는 것**이다.
그러면 안쪽 함수가 `n = n + 1` 을 할 때 자기 호출 환경에 `n` 을 새로 만들고, 호출이 끝나면
그 환경이 버려지므로 다음 호출이 또 `0` 에서 시작한다.

## 바로잡은 말

`1`, `2` 를 만드는 것은 **체인을 거슬러 올라 찾은 묶임을 제자리에서 고치는 것**이다
(`src/env.c` 57~62줄). 못 찾을 때 `false` 를 돌려주는 규칙은 따로 쓸 데가 있다.
`tests/bad-run/undefined-assign.sl` 이 그것을 쓴다.

## 곁에서 하나 더 나왔다

호출 가능 검사가 인자 평가보다 **뒤에** 돈다(`src/walk.c` 113~129줄).

```
$ cat order.sl
fun g() { print 1; return 2; }
var x = 3;
x(g());
$ ./sl --walk order.sl
[3] 오류: 함수가 아닌 값을 불렀다
1
종료 코드 70
```

표준 출력에 `1` 이 남은 뒤 오류가 난다. VM 이 인자를 밀어 넣기 전에 호출 가능 여부를
먼저 보면 표준 출력이 비어 4단계 대조가 깨진다. `study/02` 의 평가 순서 절에 없던
규칙이라 더해 두었다.
